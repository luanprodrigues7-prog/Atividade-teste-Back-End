Testes Back End

Plano de Teste (Test Plan):

É o roteiro estratégico do processo de validação. Ele funciona como o documento macro que define as diretrizes do projeto de QA.

  • O que contém: O escopo do que será testado (e o que não será), o cronograma, as ferramentas, a equipe responsável, os critérios de parada/aceitação e a análise de riscos.
  • Objetivo: Alinhar as expectativas das partes interessadas e preparar o ambiente e recursos necessários antes do início das execuções.

Casos de Teste (Test Cases)

É a especificação técnica detalhada de cenários que devem ser executados no sistema.

  • O que contém: Identificador único (ID), título descritivo, pré-condições, passos lógicos de execução e o resultado esperado. Durante o teste, registra-se também o resultado real e o status (passou/falhou).
  • Objetivo: Fornecer um guia passo a passo estruturado e repetível para que qualquer testador consiga validar uma funcionalidade sem ambiguidades.
Fundamentos de Testes de Software

Guia de Testes de Software (Back-End)

Conceitos básicos e boas práticas para iniciantes em QA

A) Documentos B) Casos de Teste C) Execução D) Monitoramento E) Resultados F) Automação

A) Documentos de Testes

A documentação garante que todo o processo de qualidade seja rastreável e transparente. Os quatro principais artefatos são:

1. Plano de Teste (Test Plan)

O roteiro estratégico do projeto de QA. Define o escopo (o que testar), o cronograma, as ferramentas, as responsabilidades e a análise de riscos.

2. Casos de Teste (Test Cases)

Especificações detalhadas de condições, passos e resultados esperados para validar uma funcionalidade específica.

3. Relatório de Incidentes de Testes (Bug Report)

O registro formal de qualquer falha ou comportamento inesperado encontrado no sistema durante as validações.

4. Relatório de Resumo de Teste (Test Summary Report)

Documento final que resume os resultados das execuções, trazendo dados sobre a qualidade do software antes de ir para produção.

B) Elaboração do Caso de Teste

Conceito: Um bom Caso de Teste deve ser claro, objetivo e facilmente replicável por qualquer pessoa da equipe. Ele descreve uma ação do usuário e a resposta esperada do sistema.

Exemplo Prático: Login no Sistema

ID: CT001

Título: Validar login com credenciais corretas.

Pré-condições: Usuário já cadastrado no banco de dados.

Passo a Passo:

  • 1. Acessar a página de login.
  • 2. Inserir o e-mail cadastrado.
  • 3. Inserir a senha correta.
  • 4. Clicar no botão "Entrar".

Resultado Esperado: O sistema autentica o usuário e o redireciona para a tela inicial.

C) Execução do Programa

Esta é a fase onde os testes saem do papel. O analista de QA segue as instruções dos Casos de Teste na aplicação real para verificar se o comportamento do software condiz com o esperado. Qualquer desvio gera a criação de um bug.

D) Monitoramento e Controle

Processo contínuo focado em acompanhar o progresso dos testes. O objetivo é comparar o ritmo real das validações com o planejamento inicial do cronograma, permitindo ações rápidas caso ocorram atrasos ou imprevistos.

E) Avaliação de Resultados

Nesta etapa, a equipe analisa se os critérios de aceitação foram atingidos. Verifica-se o volume de defeitos abertos versus fechados e a cobertura dos testes para decidir se o software está seguro e maduro para ser liberado aos usuários.

F) Comunicação com a Equipe de Automação de Testes

O alinhamento com os desenvolvedores de automação é essencial. A equipe de testes manuais repassa quais cenários são críticos, repetitivos e estão estáveis na aplicação — pois estes são os candidatos ideais para serem transformados em scripts de testes automatizados.
